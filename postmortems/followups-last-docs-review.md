# Postmortem: the last docs pull request of the follow-ups milestone

The pull request gives a live owner to every open bullet of BUILD.md that the follow-ups milestone left, records what is held for the maintainer, and corrects sentences that main makes false. It changes BUILD.md, DESIGN.md in two places and one comment in core, and adds this document. Its one review found no HIGH finding, one MEDIUM and eight LOW, and one narrow re-read of the fold and of the final pass after the merge of main found no HIGH, one MEDIUM and seven LOW. Nine are counted here. The worst are a plan entry that named evidence a reader of the public repository cannot find, and the old reason for PostgreSQL's saga walk left standing in DESIGN.md after the fold corrected it elsewhere. No code changed, so no behaviour was wrong: every finding is a sentence or a count that told a reader something false.

## Severity

Nothing a user runs was wrong. What would have shipped without the two reads is a plan and a spec that mislead their reader. The two MEDIUM findings come first. The PR3.4d entry named three flow programs "of the held branch" as the evidence for a defect main has, and the pushed branch of pull request #75 holds none of them, so a reader who looks finds nothing and may conclude the defect is not shown. DESIGN.md section 3.4, in a passage and in a row of its dialect table, and exit test line 9 still said that PostgreSQL orders a name under the database's collation and that this is why its saga reads walk, where schema version 7 made the order bytes. The seven LOW findings would have told a reader that "line 16, whose pull request merges last" points at something, which it did not; that a store still sends `heartbeat` as text and that PR3.9 landed in five PRs; that the driver loop always races a launch against its clock; that a saga step name was once refused as a bare RangeError; that `claim` holds its token by a check PR3.3c had removed; in the pull request's body, a count of Trigger sentences that did not add up; and, in this document, three claims that said more than holds.

## Root cause

A fact a document states is compared with nothing, and it is often stated in more than one place. A pull request that corrects one sentence finds the sentence it was looking at, and the same fact in another entry or in DESIGN.md stays as it was, unless the search that looks for it happens to use its words. A later pull request that changes the code does the same to every sentence it does not read. A correction also makes a claim of its own about what changed and when, and the final pass wrote one without checking it against the history it had already read. The machinery reads a plan's structure: who owns a bullet, the word DONE, the format of a heading. None of it reads what a sentence claims.

## What this round still would not catch

A sentence of BUILD.md or DESIGN.md that a later pull request makes false ships today unless someone reads it. This pull request's final pass found such sentences after four pull requests merged under it, and one of them was its own sentence that PR3.14b holds a claim token at `claim`, whose line PR3.3c had deleted. A fact stated in words that a correction's search does not use ships too, as finding 6 did. So does a pointer to evidence that is not where a reader looks, such as a branch that is not pushed, and a correction's own false claim about history, as finding 7 was. A count in prose ships until the option under PR3.10 is built, and every count outside DESIGN.md after that.
