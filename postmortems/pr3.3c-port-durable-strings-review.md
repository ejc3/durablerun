# Postmortem: PR3.3c port durable strings review

PR3.3c puts one check of every string a caller passes the store port in front of every entry of every dialect: core names each string once in a table whose type is computed from the port's, and every store extends one class whose constructor puts the check in front of each method. Its one review, a subagent running the built-in code review skill with the coordinator's probes beside it, found one HIGH, two MEDIUM and eleven LOW, of which twelve count. The one narrow re-review of the fold found nothing HIGH or MEDIUM and five LOW with two observations, which count as five. Seventeen findings, none found by the author's own machinery. The design held under both. What did not hold was the mechanism's edges: what the wrapper captures and when, what a caller can leave out, and what kind of value stands where a string or an object belongs.

**This document is adversarial toward the MACHINERY and blameless toward
people.** Never "who wrote it", "should have noticed", "was careless" — those
explain nothing and are not actionable. Always "what would have made this
unwritable, or caught it without a human looking". Every section below asks a
question whose comfortable answer is the wrong one; if a section is easy to
fill in, it has not been answered yet.

## Severity

The worst would have turned CI red and, merged past that, broken test doubles in silence. The wrapper captured each entry when a store was constructed, so a method patched onto a store class afterwards was never reached. One dogfood case injects an outage exactly that way, and it failed on the reviewed head. The author's local gate list ran core, the SDK, the driver and conformance, and not the dogfood app, so the first run of that suite on this branch was the reviewer's.

Second, a regression in durable state. The author's own simplify fold deleted core's second copies of the port's check, because three registered mutations could not be killed behind the one check. The copies had also refused a child spawn's parent whose member was left out. With them gone, a spawn whose replay key was left out was sent under a stored key that ends in the word undefined, on three dialects, where the base refused it by name.

Third, a class field that overrides an entry replaced the check without a word, and the replacement was handed a queue with a NUL in it. The author had written that the compiler refuses that shape. It does not.

Fourth, from the re-review, the same two classes again, smaller. The fix for a live read of the array iterator left a second live read in the same constructor, a descriptor literal that inherits from `Object.prototype`, and the table was frozen at its outer object only. And a value of the wrong kind still passed: a number, a string or an array where a spawn's options belong was accepted as if empty options had been passed, and a payload of null was reported as an outage, which is the harm this pull request exists to end.

The remaining nine are sentences and counts that said more, or other, than was true.

## Recurrence

A value of a kind the port's type forbids reaches an entry: this class recurred INSIDE this pull request, twice. Before any review the author made the check refuse a value that is not a string where a string was passed. The first review found the value that is not there at all (finding 2). The re-review found the value that is not an object where an object belongs, and the value that is not a string where a payload belongs (finding 14). Each round closed the kinds that round had named. The property is wider: every argument of every method, given every kind of value its TypeScript type forbids, answers a refusal of the family before anything is sent. The table is of strings, so an argument that carries none is outside it, and the audit below shows what that leaves.

A live read of the realm in a file that otherwise calls captured intrinsics: this class recurred inside this pull request. Finding 9 was the array iterator, and its fix was an indexed loop. Finding 13 was the next line but one of the same constructor, a descriptor literal. The fix for 9 was a point fix of the route the review had named. Nothing reads core's files for a live read: the user boundary lint covers one directory and two names. It is not built, and BUILD.md does not yet plan it, so the next such read will be found by a reader or by nobody.

A generated surface that draws its expectation from the source it checks: this class recurred inside this pull request. Earlier rounds on main met the neighbouring class under another name, a hold that cannot fail (pull request 63).

A check kept in series behind another hides its mutant: this class recurred twice at the end of this pull request, and the author's machinery caught both. At the merge, main's reader of `failRollback`'s argument refuses a wrong shape, and the one check now stands in front of it and refuses the same call first, as a step that was left out, so the mutation that stops the reader refusing could no longer be seen through a store. ## Root cause

The mechanism was designed around one question, which strings enter the port and where, and it answers that question well: the table's type stops the build for a string nobody named, and both reviews failed to bend it. Every behaviour finding is about something beside that question. What the wrapper holds on to, and when (1, 3, 9, 13). What stands at a place when it is not a string of the right kind: nothing, a number, null, an array (2, 14). What a generated case compares with (17). The author's cases were generated from the table, so they asked what the table can say, and the table cannot say any of those. A surface generated from a model inherits the model's blind spots exactly, and a second, smaller instrument that does not come from the model, a probe over the real class with hostile values, is what both reviewers used and the author did not.

The second cause is the local gate list. It was written by hand from the packages the change touches, and the suite that failed was in a package the change does not touch. CI's verify job runs every suite. The local list is a convenience, and it was read as evidence.

## Mechanisms

Built in this PR:

- The entry is looked up when it is called, behind an accessor that cannot be defined again, built from a descriptor that inherits nothing, in a constructor that loops by index, over a table that is frozen throughout. Rung 1 at run time for the accessor, rung 3 for the five core cases and their five mutations. `packages/core/src/port-strings.ts`.
- The table marks what a caller may leave out, and the mark is computed from the port's type in both directions, so a mark the type does not have, and one it has that the table lacks, each stop the build. A map of strings takes a map's name and a string a string's. Rung 1.
- One check of every string place, whatever its rule, refuses a value that is not a string, one left out among them, and the check refuses a value that is not an object where an options object belongs. The identifier surface asks all 82 places and the four options objects left out, and each payload's place null and a number, on every dialect. Rung 2, generated from the table.
- The options objects are written down by place beside the counts of places. Rung 3, and a second copy written by hand.
- The author's local gate list runs the dogfood app and the harness. A list, and no rung.

Deferred (recorded in BUILD.md):

- The wrapper handing the entry a copy of each options object it read, so that the entry cannot read what was not checked. Its trigger is a store handed to code its owner does not trust. Today a caller that can pass such an object already holds the store.
- Deleting the refusal inside core's reader of a failed rollback's argument, which is dead behind the one check for every call through a store. Its trigger is the reader losing its last direct caller.
- A surface generated from the port's TYPE and not from the table of strings: every argument of every method, given each kind of value its type forbids, answers a refusal of the family before anything is sent. Its trigger is the first report of a wrong-kind argument, such as null for `claim`'s options, that reads as a bug in the engine. It is its own change, because most of those arguments are numbers and durations with checks and refusal types of their own.

- A defect at an argument that carries no string would ship today. `claim('q', 'w', null)` is a TypeError from inside the entry, outside the refusal family, and a hosted route that forwarded such a value would answer it 500. No hosted route does.
- A new live read of the realm in core would ship today. Nothing reads core's files for one. Two reviews found one each.
- An entry called from a store class's prototype is reached with nothing in front of it, and no test lists every such call in the repository.
- A caller that answers a clean string to the check and another to the entry stores what was never checked.
- Two names of one rule that change places in the table would ship today with every case green. Only the name inside the refusal would be wrong.
- A thing the port takes that nobody wrote down beside the generated places is held by nothing, as the options objects were until the re-review.
- A refusal added in front of another would ship with the other's mutation unable to fail, until the unfiltered audit runs: the hand run of a new mutation does not run the old ones whose checks it can shadow.
- A false sentence in a document would ship today, as in every round before this one.
