# Postmortem: the typed store access refusal (PR5.6), one review

The pull request gives a store's refusal of a credential a type of its own. Before it, a wrong token or password was typed an outage, which every caller repeats, and a statement the role may not run was typed a permanent answer of one task. The change types both an access refusal on libSQL, PostgreSQL and MySQL, gives the CLI exit 4 for it, and pins the commit the week's workflow runs. One review read the branch, as a subagent invoking the built-in code review skill. It found nine things: none HIGH, three MEDIUM and six LOW. Each MEDIUM is a refusal of a credential that is still not typed one, and each was shown by a run. One of the three is fixed here, and the other two are the same on main, so they are held by cases and recorded for a later change.

**This document is adversarial toward the MACHINERY and blameless toward people.** Never "who wrote it", "should have noticed", "was careless" — those explain nothing and are not actionable. Always "what would have made this unwritable, or caught it without a human looking". Every section below asks a question whose comfortable answer is the wrong one; if a section is easy to fill in, it has not been answered yet.

## Severity

Finding 1 is the worst, and it would have shipped. A gateway in front of a libSQL server answers a refused token with 401 and a JSON body that has a `message` member. The client's error for that answer carries no status, so the executor typed it by the text of the body. The usual text made it an outage: the CLI exits 6, which the README calls safe to repeat, and a job repeats a token that will never be accepted. Text with the wording of a missing version table made it a database that was never initialized on the version read, which core's version read takes for a fresh database. Other text made it a schema fault or a permanent answer. By the review's reading, the hosted server whose answers DESIGN.md records and the server's own JSON body with an `error` member are not affected, so the week itself was not at risk.

Findings 2 and 3 are the same on main, and what would have shipped is a sentence. DESIGN.md said a refused login and a statement the role has no privilege for are typed on PostgreSQL. A URL with no password against a server that asks for one is an outage, and a role with no USAGE on the store's schema is read as a schema fault, and on the version read as a fresh database. An operator who reads the document would expect exit 4 for both and get 6 and 5.

Finding 6 lets a person who can set the repository's variables run a commit main never held with the week's token. Finding 7 leaves a role that can log in, with a password written in the test's source, on a server other tests share. Findings 4, 5, 8 and 9 are a recorded choice, two sentences that said more than was measured, and a second copy of a list.

## Recurrence

A claim wider than its mechanism or its measurement recurred, in findings 2, 3, 5 and 9. The previous round named the class for exit test lines and wrote: "Nothing reads a line's promise against its cases, so the class will recur in the next record." It recurred in the next pull request, in DESIGN.md and the README, where the answer had been to write the line more carefully. What this round adds for two of the four is a case on a real server for each sentence of the refusal list. That is a check of today's sentences. The tie from a sentence to its case is still made by hand, so a new sentence has no case until someone writes one. The previous round wrote that every round after the record of the operable alpha corrected such lines after they were built. This round did the same, and nothing built here stops the next.

A second copy of one list recurred, in finding 8. PR5.4's findings 9 and 14, PR5.5's finding 8 and the previous round's finding 6 name the class. This pull request's own simplification pass looked at writing the 23 numbers once and rejected it, because a copy in the registry means a number dropped from the executor cannot drop its own mutation. That reason holds for a number dropped and not for a number added, and the copy was left with a count as its only tie. The mechanism the class has had each time is a count or a rule to keep the copies equal, and a count that the same edit updates is not a check. The equality check added now reads one literal of the executor by its text, which is closer to the property and is still a picture of it.

A generated surface that holds one dimension to one value recurred, in finding 1. PR5.3d's round met it in its fixes, each "held by a case built for that instance", with "the one code of a 500, the one value of an option" among its examples. Its answer there was to widen the named case. The same answer is given here, twelve body shapes where there was one, and the same limit holds: the shapes are listed, not generated. The stronger half of this round's answer is the fetch, which takes the dimension away for a client the executor opens.

Finding 6 is a false negative of a mechanism the previous round asked for. Its audit of the pinned commit listed one false negative, a variable changed in the middle of the week. That a commit can be pinned which main never held was not listed. The pin was the property "one commit prints every document", and the reader took it for "main's commit prints every document".

A test fixture that leaves a login on a server other tests share, finding 7, is not a class this round found in an earlier postmortem.

## Fix-induced defects

None of the nine findings was made by a fix of this round, because one review made one round.

The fold made one defect of its own, in a test, and the author's machinery found it before any review. The red test commit of finding 1 added a control that claimed to show a 401 on the client's version requests is still taken as a version the server does not speak. A plant found it empty: a fetch that threw on a refused status passed it, because the client at the pinned version sends no version request. The commit after the fix replaces it with two cases that call the fetch by itself, and corrects the comment and the sentence of DESIGN.md that said the client asks for versions through the fetch.

The fold's fixes are new code, and no review has read them when this is written. They were tested again and not reviewed again: each new check was bent once and seen failing by name. A second read of the fix for finding 1 follows this document.

## Root cause

Each claim and each generated case was written from the one answer that had been measured. The libSQL case sent one body shape. The PostgreSQL sentences were written from one login that fails, a wrong password, and one role that lacks a privilege, one with USAGE and no SELECT. The README's sentence was written from two tokens. The workflow's cases were written from the one property the previous round asked for. In each place the measured answer was true, and the sentence or the case built on it said "every" where the measurement said "this one".

No layer asks what else can vary. The generated case multiplies the dimensions its author listed, and a dimension that was not listed has one value without anything saying so. The mutation audit bends the code that exists and cannot bend a body shape nobody sent. The cases that read DESIGN.md hold its counts and its names, not what its sentences promise. So a refusal that arrives by a road the author did not measure passes every gate, and it is found by a reader who asks what else a server may send.

## What this round still would not catch

A libSQL refusal whose handling depends on something no listed shape varies would ship today: the length of the body, a header, a status the fetch does not name. A client made outside the executor still types a gateway's 401 an outage.

A sentence of DESIGN.md or the README that promises a typed answer nobody measured would ship today, as two did before this review. A PostgreSQL login the driver declines to send, and a role with no USAGE on the schema, are still not access refusals, and a MySQL refusal whose name has none of the pattern's words is still an outage.

The week's workflow would run a commit of a merged branch at which main never stood, a failing test before its fix among them, and would keep as a report a file named `week-*` that a step of the pinned commit writes. A number added to the MySQL list by any road but the literal gets no mutation. A test process that ends before its fixture closes leaves a login on the shared server.

The fold itself is new code. Its fix for finding 1 is to be read once more, and the rest of it is held by its own cases and plants alone.
